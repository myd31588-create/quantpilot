# 我给回测做了个体检：为什么大部分量化策略的收益都是假的

> 打开任何一个量化开源项目，你看到的都是净值曲线和年化收益。
> 但几乎没有人回答那个更要紧的问题：**这个数字，会不会是你自己骗自己？**

我做了个工具，专门回答这个问题。它不选股，只给回测做体检。

---

## 一、五种"合法的作弊"

量化里有五件事，你做了也不违法、没人管，但收益会凭空变好看：

**1. 前视偏差**
用当天收盘价算信号，又假设当天开盘就能成交。等于你能看见未来，然后回到过去下单。

**2. 幸存者偏差**
只下载现在还活着的股票。那些退市、ST、跌成仙股的，统统不在样本里。你的回测天然只包含"活下来的人"。

**3. 过拟合**
调了 30 次参数，挑出最好的一组，然后把这个结果当成"策略的表现"。

**4. 忽略成本**
假设零手续费、零滑点、想买就买得到。真实世界里，光印花税和佣金就能吃掉几个点。

**5. 样本内当样本外**
用 2015–2025 全样本调参，然后报告这十年的收益，还管这叫"验证"。

这五件事有个共同点：**它们都不会让你报错。** 代码跑得通，曲线很漂亮，你甚至会真的相信自己找到了圣杯。

---

## 二、所以我做了五项检查

思路很直接：**既然作弊不会报错，那就专门写测试去抓它。**

| 检查 | 抓什么 | 怎么实现 |
|---|---|---|
| **信号滞后** | 前视偏差 | 把选股信号整体延后 1 天、2 天重跑，看结果波动多大 |
| **随机化对照** | 运气冒充能力 | 同股票池、同调仓频率，随机选股跑 60 次，算 p 值 |
| **参数敏感性** | 过拟合 | Top N 从 5 扫到 30，看收益离散度 |
| **成本敏感度** | 靠零成本撑收益 | 佣金、印花税、滑点全部 ×3 再跑 |
| **幸存者偏差** | 样本里只有活人 | 统计数据集中退市股票占比，为 0 直接标红 |

最后输出一个 0–100 的可信度评分。

### 信号滞后：最狠的一项

逻辑是这样的：一个稳健的策略，信号晚一天执行，收益应该平滑变化。

如果——**晚一天，收益直接腰斩**，说明原策略在偷看未来。

但这里有个我没想周全的地方：我第一版只判断"收益是不是下滑"。

结果跑出来一组数：滞后 0 天 −16.5%，滞后 1 天 −3.3%，**滞后 2 天 +43%**。

我的判定：**PASS**。因为收益是上升的，没满足"下滑超过 15%"的条件。

这显然错了。**一个策略如果对执行时点敏感到几十个百分点，无论变好还是变坏，它都是不稳的。** 后来改成看最大偏差，立刻判 FAIL。

> 这个 bug 本身比功能更有意思：**判定条件写得太"聪明"，反而会漏掉最明显的问题。**

### 随机化对照：用蒙特卡洛打脸

做法很朴素：既然你是"多因子打分取 Top 10"，那我把选股换成"随机选 10 只"，其他一切不变——同样的股票池、同样的过滤、同样的调仓日、同样的手续费。

跑 60 次，得到随机策略的收益分布。然后看你的策略落在哪。

- p < 0.05：你的选股能力显著，不是运气
- p > 0.2：**你跑不赢随机选股**，那这套因子就是白干的

60 次回测在我的机器上只要 1.6 秒——并行流跑，一个核一个回测。

### 参数敏感性：悬崖还是平原

把 Top N 从 5 扫到 30，看收益曲线。

- 参数变了收益也平稳 → 策略捕捉的是真实现象
- **只有某一档特别好，邻居全崩** → 那是拟合出来的坑，不是路

## 三、测自己的策略：30 分

我把这套检查用在自己的策略上（动量 + 波动率 + 换手 + 估值，六因子等权，月度调仓）：

```
评分：30 / 100（需要警惕）

FAIL  信号滞后检验   滞后 0/1/2 天：-16.50% / -3.32% / +42.96%，最大偏差 59.5 个百分点
FAIL  随机化对照     60 次随机选股中位数 -2.03%，策略 -16.50%，p = 0.82
PASS  参数敏感性     Top N 扫描相对稳定
WARN  成本敏感度     成本 ×3 后收益由 -16.50% 变为 -32.93%
WARN  幸存者偏差     股票池 60 只，退市 0 只
```

**结论：这个策略不具备选股能力，收益也无法区分于随机。**

而且这个结论是诚实的——我用的本来就是模拟数据（随机游走），里面根本没有真实因子收益。

但请注意：**很多人拿真实数据跑出 +30%，然后开心地贴到 README 上。** 如果他们的数据里也有前视偏差、也漏了退市股，那 +30% 的可信度和我的 −16.5% 是一样的。

**体检的价值不在于让你的策略变好，而在于告诉你：它现在到底是不是真的。**

## 四、一个让我后背发凉的 bug

写测试的时候我加过一条断言：

```java
assertEquals(1.0, r.nav().get(0).nav(), 1e-9);   // 首日净值应该是 1
```

它一直是绿的。

后来我读代码发现建仓逻辑有个问题：

```java
long shares = (long) Math.floor(perStock / price / LOT_SIZE) * LOT_SIZE;
double amount = price * shares;
double fee = Math.max(minCommission, amount * commissionRate);
if (amount + fee > cash) {
    continue;          // ← 整仓被跳过
}
```

按预算算出的手数，加上手续费会略微超出总现金，于是这一只直接不买了，钱闲置着。

**而首日净值恰好还是 1.0——因为一分钱都没花出去。**

也就是说：**这条测试通过，恰恰是因为 bug 存在。**

修完之后，首日净值变成 0.99875（扣了手续费和滑点），断言立刻挂了。

这件事我印象很深：**测试通过不等于逻辑正确，有时候它只是恰好掩盖了错误。**

## 五、最后

做这个东西最大的收获，不是学会了写回测。

是意识到：**在量化里，最贵的能力不是发现机会，是怀疑自己。**

你的策略会赚钱，可能是因为你真的聪明，也可能是因为：
- 数据里少了三百只退市股
- 你在收盘后用了收盘价，却假装在开盘买入
- 你调了 40 次参数，只留下了最幸运的那一次

这些都不会报错。它们只会让你的曲线更漂亮。

所以比起"我的策略年化多少"，我更愿意回答另一个问题：

> **如果有人拿放大镜看我的回测，他能挑出什么毛病？**

能提前把答案写出来，才算真的做完了。
